# Материалы и отметки чтения

`material-status.js` объединяет 118 архивных единиц: 74 вопроса повесток,
33 пункта плана культуры, 8 информационных тем и 3 тематические подборки.
Карточки и подборки показывают «Новое», «Обновлено» или «Прочитано».
«Новое» означает отсутствие отметки чтения на этом устройстве, а не свежую
дату документа. Архивные даты и оговорки остаются видимыми.

Чтение отмечается только кнопкой «Отметить прочитанным». Повторное нажатие
снимает отметку. Загрузка, раскрытие подробностей, навигация, поиск, прокрутка
и переход к источнику её не меняют. Действие обновляет только статус,
сохраняя открытые блоки, вводимые заметки и фокус кнопки.

## Стабильность и версии

- Существующие ID вопросов, `personal.read` («Изучено»), выбранные вопросы,
  заметки, статусы и ключ `deputat-materials-v1` сохранены.
- `material-baselines.js` содержит версии исходных вопросов из commit
  `fc5f02e259869366cdc8608bd51a9327e3ebcb52`. Не регенерировать этот файл:
  иначе старые отметки могут ошибочно примениться к обновлённому тексту.
- Первый запуск фиксирует снимок legacy-отметок в
  `deputat-material-read-legacy-v1`. После миграции «Изучено» и «Прочитано»
  независимы. Исходное legacy-хранилище при миграции не переписывается.
- Версия — детерминированный отпечаток содержания, включая даты и источник.
  Изменение содержания делает старую отметку «Обновлено», остальные сохраняются.
- У трёх подборок есть явная `revision` в `material-status.js`. При изменении
  текстов, находящихся непосредственно в `materials.js` (например, сводки ЕДДС
  или инициативы учителей), увеличивать соответствующую revision. Изменения
  структурированных данных также обнаруживаются по отпечатку.
- Для плана 22–28 июня используется пространство
  `culture-plan-2026-06-22:culture-1…33`. ID `culture-1…33` остаются в исходных
  данных для существующих действий. Для следующего плана создать новое
  пространство и собственные ID; не перенумеровывать существующие записи.
- Каждый новый материал получает неизменный ID; изменение даты, заголовка
  или порядка отображения не является основанием менять его ID.

Отметки чтения используют отдельный ключ `deputat-material-read-v1:<ID>` на
каждый материал. Это исключает перезапись отметок других материалов при
одновременной работе вкладок. `storage` обновляет видимые статусы другой
вкладки; при одновременной записи одного ID действует последняя запись.
При отказе localStorage отметка остаётся в памяти страницы, показывается
сообщение. Между устройствами и браузерами синхронизации нет.

## Будущие публичные муниципальные новости

`public-news.js` сейчас содержит пустой массив. Новостей с подтверждёнными
публичными источниками в этой доработке не добавлено. Пример схемы (не публикация):

```js
{
  id: 'news:municipal-road-report-2026-10', // постоянный ID, не индекс массива
  version: 1,                           // увеличить при содержательной правке
  addedAt: '2026-10-02',                 // дата добавления на сайт
  publishedAt: '2026-10-01',             // дата публикации источника
  updatedAt: '2026-10-01',               // дата изменения содержания
  title: 'Заголовок публичной публикации',
  summary: 'Проверенное краткое изложение, без личных данных.',
  source: { name: 'Название муниципального источника', url: 'https://…' }
}
```

Перед добавлением проверить доступность первоисточника без авторизации,
точность дат, содержания и статуса (проект, план, принятое решение или отчёт).
Ссылка должна вести к конкретной публичной публикации. Код требует HTTPS,
не допускает credentials в URL, проверяет календарные даты и уникальность ID.
Текст экранируется при отображении. Дата добавления не подменяет дату документа.
Ошибочная запись отклоняется; проверить тестами до публикации.

Не переносить личные письма, темы частных писем, скриншоты переписки, финансовые
данные физических лиц, сведения жителей или секреты. Для новых публикаций
использовать только публичные муниципальные источники. Существующему архиву
не приписываются неизвестные официальные URL; старые данные не изменены.
Повестки и планы не подтверждают принятие решений, завершение работ или
передачу мандата Ивану.

## Проверка

Сайт не требует сборки. Тесты требуют уже установленный `jsdom` и `playwright`
(их можно указать переменными `JSDOM_PATH` и `PLAYWRIGHT_PATH`).

```sh
node tests/material-status.cjs
python3 -m http.server 4193
# в другом терминале; CHROME_PATH указывает на локальный Chromium при необходимости
node tests/browser.cjs
```

DOM-тесты проверяют миграцию, сохранность заметок и выбора, явное чтение и
снятие отметки, повторное открытие, обновление содержания, независимость
«Изучено», события вкладок, 12 маршрутов, новые новости, ошибки хранилища,
валидацию источника и дат. Chromium проверяет реальное взаимодействие двух
вкладок, Enter и сохранение фокуса/disclosure, бюджетный поиск, back/forward,
7 разделов при 320/390/1280 px и отсутствие ошибок страницы.
